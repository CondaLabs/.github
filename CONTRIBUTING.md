# Contributing to CondaLabs

Thank you for your interest in contributing to CondaLabs projects. Contributions of all kinds are welcome, including bug reports, feature suggestions, documentation improvements, and code changes.

We appreciate everyone who takes the time to help improve our projects.

## Before Contributing

Before submitting a contribution:

1. Check the project's README for an overview and setup instructions.
2. Review existing issues and pull requests to avoid duplicating work.
3. Check the project's documentation for any specific contribution guidelines.
4. For significant changes, consider opening an issue first to discuss your proposal.

## Reporting Bugs

If you encounter a bug:

1. Check whether it has already been reported.
2. Open an issue in the relevant repository.
3. Provide a clear description of the problem.
4. Include steps to reproduce the issue.
5. Include relevant screenshots, logs, or error messages when applicable.
6. Mention your environment and the affected version.

Please avoid including sensitive information in bug reports.

## Suggesting Features

Feature suggestions are welcome.

When submitting a feature request, explain:

- The problem or need the feature addresses.
- How you expect the feature to work.
- Why it would be useful.
- Any relevant examples or references.

## Submitting Changes

If you want to contribute code or documentation:

1. Fork the relevant repository.
2. Create a separate branch for your changes.
3. Make your changes while following the project's existing conventions.
4. Test your changes where applicable.
5. Keep commits focused and provide meaningful commit messages.
6. Submit a pull request with a clear description of your changes.

Please include relevant screenshots or testing details when they help explain your contribution.

## Pull Request Guidelines

To help us review contributions efficiently:

- Keep pull requests focused on a specific change.
- Explain what was changed and why.
- Link related issues when applicable.
- Make sure existing functionality is not unintentionally affected.
- Address review feedback when requested.

Pull requests are subject to review and may be accepted, revised, or declined.

## Code Quality

Contributors are encouraged to:

- Follow the coding style and conventions already used in the project.
- Write clear, maintainable, and well-structured code.
- Avoid unnecessary dependencies.
- Update documentation when behaviour or functionality changes.
- Include tests when appropriate.

Individual projects may have additional requirements.

## Community Standards

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

Be respectful, constructive, and considerate when interacting with others.

## Questions

If you have questions about contributing to a particular project, open an issue in its repository or refer to its project-specific documentation.

Thank you for helping make CondaLabs projects better.

---

*These guidelines apply across CondaLabs repositories unless a project provides its own contribution guidelines.*
